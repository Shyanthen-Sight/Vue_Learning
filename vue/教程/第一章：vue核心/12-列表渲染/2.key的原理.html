v-for 中 key 的作用与原理

动手试试：先在两个列表的输入框里随便打几个字，再点下面的按钮，观察输入框里的内容怎么变。

① :key="p.id"（正确用法）

  • {{p.name}}-{{p.age}}

② :key="index"（不推荐）

  • {{p.name}}-{{p.age}}

一、key 是什么

key 是每个虚拟 DOM（vnode）对象的唯一标识。数据变化后，Vue 会拿「新的虚拟 DOM」和「旧的虚拟 DOM」做 diff 差异对比，而对比时就是靠 key 来认"哪个节点是哪条数据"。

二、diff 对比规则

① 在旧虚拟 DOM 中找到了相同 key 的节点：

  • 内容没变 → 直接复用之前的真实 DOM（不重新创建，省性能）
  • 内容变了 → 生成新的真实 DOM 替换掉旧的

② 在旧虚拟 DOM 中没找到相同 key 的节点：创建新的真实 DOM 渲染到页面。

三、用 index 作为 key 的问题

当对列表做逆序添加、逆序删除等破坏原有顺序的操作时：

  • 会产生没有必要的真实 DOM 更新 —— 界面效果没问题，但效率低（上面的对比里可看到 index 从 0 开始重新排，所有 li 都被误判为"变了"）
  • 如果列表里有输入框等带状态的 DOM，会出现内容错位 —— 这就是你在上面演示里看到的现象：① 正常，② 老刘借走了你打过的字

四、开发中怎么选 key

  • 最好用每条数据唯一的标识，如 id、身份证号、手机号、学号等
  • 如果数据只是纯展示、从不做逆序增删，用 index 也没问题
