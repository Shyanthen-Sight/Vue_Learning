# 《列表过滤与排序》代码详解

> 对应文件：[教程/12-列表渲染/3.列表过滤 -排序.html](./教程/12-列表渲染/3.列表过滤%20-排序.html)
> 功能：输入关键字**过滤**人员列表，点击按钮按年龄**升序 / 降序 / 原顺序**排列。

---

## 一、整体效果

页面由三部分组成：

```
┌──────────────────────────────────────────┐
│  人员列表                                │
│  [请输入搜索的名字________]  ← 搜索框     │
│  [年龄升序] [年龄降序] [原顺序]   ← 按钮   │
│                                          │
│  · 马冬梅-30-女                          │
│  · 周杰伦-18-男        ← 列表结果        │
│  · 周星驰-45-男                          │
│  · 温兆伦-22-男                          │
└──────────────────────────────────────────┘
```

- 在搜索框输入 "周"，列表立刻只剩下名字带 "周" 的人；
- 点 "年龄升序"，剩余的人按年龄从小到大排；
- 点 "原顺序"，恢复过滤后的原始顺序。

全程**不刷新页面**，所有变化都是 Vue 响应式地实时更新。

## 二、代码结构总览

整个文件是一个**单 HTML 文件**，分了三个大块：

| 块 | 标签 | 作用 |
|----|------|------|
| 样式 | `<style>` | 简单美化页面 |
| 模板 | `<body>` 里的 `<div id="root">` | 页面结构，放 Vue 的模板语法 |
| 逻辑 | `<script>` | 创建 Vue 实例，定义数据、计算属性 |

```html
<div id="root">   <!-- 模板：Vue 把这里的内容接管 -->
  ...
</div>

<script>
  const vm = new Vue({
    el: "#root",      // 告诉 Vue：去接管 id="root" 这个区域
    data: { ... },    // 数据
    computed: { ... } // 计算属性
  })
</script>
```

## 三、模板部分逐行讲解

```html
<div id="root">
  <h2>人员列表</h2>

  <input type="text" placeholder="请输入搜索的名字" v-model="keyWord">
  <button @click="sorttype='asc'">年龄升序</button>
  <button @click="sorttype='desc'">年龄降序</button>
  <button @click="sorttype=''">原顺序</button>

  <ul>
    <li v-for="p in filPersons" :key="p.id">
      {{p.name}}-{{p.age}}-{{p.gender}}
    </li>
  </ul>
</div>
```

### 1. `v-model="keyWord"` —— 双向数据绑定

- `v-model` 把输入框的**值**和 `data` 里的 `keyWord` 绑在一起；
- 用户在输入框打字 → `keyWord` 自动更新；
- `keyWord` 变 → 依赖它的计算属性 `filPersons` 自动重算 → 页面列表自动刷新。

这就是"**双向**"：输入影响数据，数据反过来影响显示。

### 2. `@click="sorttype='asc'"` —— 点击事件

- `@click` 是 `v-on:click` 的简写，绑定点击事件；
- 等号后面是一句**表达式**，点击时直接给 `sorttype` 赋值；
- 三个按钮分别赋 `'asc'`（升序）、`'desc'`（降序）、`''`（原顺序）。

```js
@click="sorttype='asc'"   // 点击 → sorttype 变成 'asc'
```

### 3. `v-for="p in filPersons"` —— 列表渲染

- `v-for` 遍历**计算属性** `filPersons` 返回的数组，`p` 是数组里的每一个人员对象；
- `:key="p.id"` 给每个 `li` 一个唯一标识（用人员的 id），Vue 用它高效地复用和更新 DOM；
- `{{p.name}}-{{p.age}}-{{p.gender}}` 是插值语法，把对象的属性显示出来。

> **关键点**：遍历的是 `filPersons`（过滤+排序后的结果），不是原始的 `persons`。

## 四、数据部分

```js
data: {
  sorttype: '',  // ''是原顺序, asc是升序, desc是降序
  keyWord: '',   // 搜索关键字
  persons: [     // 原始数据（永远不被改动）
    { id: '001', name: '马冬梅', age: 30, gender: '女' },
    { id: '002', name: '周杰伦', age: 18, gender: '男' },
    { id: '003', name: '周星驰', age: 45, gender: '男' },
    { id: '004', name: '温兆伦', age: 22, gender: '男' }
  ]
}
```

| 字段 | 类型 | 含义 |
|------|------|------|
| `sorttype` | 字符串 | 当前排序方式，`''`/`'asc'`/`'desc'` 三种取值 |
| `keyWord` | 字符串 | 搜索关键字，和输入框 `v-model` 绑定 |
| `persons` | 数组 | **原始数据**，存放所有人员，永远不被改动 |

`persons` 注释特意写了"永远不被改动"——这是本项目最重要的设计原则，下文会重点解释。

## 五、计算属性 `filPersons`（核心逻辑）

```js
computed: {
  filPersons() {
    // 第一步：先过滤（filter 返回新数组，不会改动原数据 persons）
    const arr = this.persons.filter(p => p.name.includes(this.keyWord))

    // 第二步：再根据 sorttype 排序
    if (this.sorttype === 'asc') {
      arr.sort((p1, p2) => p1.age - p2.age)  // 升序
    } else if (this.sorttype === 'desc') {
      arr.sort((p1, p2) => p2.age - p1.age)  // 降序
    }
    // 原顺序：什么都不做，保持过滤后的顺序

    return arr
  }
}
```

### 1. 什么是计算属性（computed）？

- 它是一个**函数**，但用法上像 `data` 里的属性一样：模板里写 `filPersons`，不需要加括号；
- 它**依赖别的数据**（`keyWord`、`sorttype`、`persons`），这些数据一变，它自动重新计算；
- 有**缓存**：依赖没变时不会重复计算，性能好。

> 换句话说：计算属性 = "根据已有数据推导出来的新数据"。

### 2. 第一步：过滤 `filter`

```js
const arr = this.persons.filter(p => p.name.includes(this.keyWord))
```

拆开看：

- `this.persons`：拿到原始数组；
- `.filter(回调)`：**遍历**数组，把回调返回 `true` 的元素挑出来，组成一个**新数组**返回；
- `p => p.name.includes(this.keyWord)`：回调函数，判断"这个人的名字是否包含关键字"。

> `includes` 是字符串方法：`'周杰伦'.includes('周')` 返回 `true`，`'马冬梅'.includes('周')` 返回 `false`。

**举例**：如果 `keyWord = '周'`，结果：

```js
[
  { id: '002', name: '周杰伦', age: 18, gender: '男' },
  { id: '003', name: '周星驰', age: 45, gender: '男' }
]
```

**重点**：`filter` 返回的是**新数组**，原 `persons` 一点没动。

### 3. 第二步：排序 `sort`

```js
if (this.sorttype === 'asc') {
  arr.sort((p1, p2) => p1.age - p2.age)  // 升序
} else if (this.sorttype === 'desc') {
  arr.sort((p1, p2) => p2.age - p1.age)  // 降序
}
```

`sort` 是数组方法，传入一个**比较函数**。`sort` 会成对地取数组里的元素，调这个比较函数来决定先后：

| 比较函数的返回值 | 含义 | 谁排前面 |
|------------------|------|----------|
| 负数 | 前一个"更小" | 前一个 |
| 正数 | 后一个"更小" | 后一个 |
| 0 | 一样大 | 顺序不变 |

**升序** `p1.age - p2.age`：
- 若 `p1.age=30, p2.age=18` → `30-18=12`（正数）→ 18 排前面 → 小的在前，大的在后 ✅ 升序
- 若 `p1.age=18, p2.age=30` → `18-30=-12`（负数）→ 18 排前面 ✅

**降序** `p2.age - p1.age`：正好反过来，大的排前面。

> **补充**：`sort` 会**原地**修改数组。但因为 `arr` 是 `filter` 出来的新数组，所以排序同样不会影响原始 `persons`。

### 4. 返回结果

```js
return arr
```

计算属性最终把"过滤 + 排序后"的数组交给模板的 `v-for` 渲染。

## 六、整体数据流（最重要的一张图）

```
原始数据 persons（data 中，永不被改动）
        │
        │ ① 用户输入关键字 → keyWord 变化
        ▼
   filter：筛选出名字包含关键字的元素
   （返回新数组 arr，不影响 persons）
        │
        │ ② 用户点击按钮 → sorttype 变化
        ▼
   sort：按 sorttype 升序 / 降序 / 不动
   （原地排序 arr，仍然不影响 persons）
        │
        ▼
   filPersons 返回结果
        │
        │ ③ Vue 检测到计算属性依赖变化，自动重算
        ▼
   v-for 重新渲染页面列表
```

**触发链条**：用户输入/点击 → 数据变 → 计算属性重算 → 页面刷新。这就是 Vue 响应式的核心。

## 七、设计亮点与为什么这么做

### 1. 为什么不直接修改 `persons`？

因为数据是"源头"。如果一边过滤一边删掉 `persons` 里的元素，再想恢复、再想排序，数据就没了。**保持原数据纯净，才能随时重新推导出任何想要的视图。**

### 2. 为什么用计算属性而不是方法（methods）？

- 计算属性**有缓存**：`keyWord`、`sorttype` 没变时，即使多次访问也不会重复算；
- 计算属性在模板里用起来像普通属性（不加括号），更直观；
- 模板里 `v-for`、插值多处引用时，都指向同一份计算结果。

### 3. "过滤+排序"为什么用两个步骤分开写？

- 逻辑清晰：先解决"筛选出哪些人"，再解决"这些人按什么顺序排"；
- 两个步骤互不干扰，`sort` 是在过滤后的结果上排的，语义正确。

### 4. `:key="p.id"` 有什么用？

列表需要唯一的 key，Vue 才能精准地复用、移动、更新 DOM 节点，而不是整段重建，性能更好也更少出 bug。**永远别用 index 当 key**（排序会打乱 index 的对应关系，容易出问题）。

## 九、常见问题速查

| 问题 | 原因 / 解答 |
|------|-------------|
| 搜索没反应？ | 确认输入框写了 `v-model`，且名字确实包含关键字 |
| 点按钮没反应？ | 确认 `@click` 里赋值的是 `sorttype`，且按钮内用到的是 `filPersons` |
| 排序和过滤冲突吗？ | 不冲突，先过滤后排序，两步独立 |
| 排序会改原始数据吗？ | 不会，`filter` 生成了新数组，`sort` 只排新数组 |
| 为什么列表顺序偶尔"怪怪的"？ | 检查是否用了 `index` 当 `:key`，应改用唯一 id |
| 中文排序准不准？ | 本示例只按数字 `age` 排，若按中文名排序需要 `localeCompare` |

## 十、延伸：如果按名字排序

```js
if (this.sorttype === 'asc') {
  arr.sort((p1, p2) => p1.name.localeCompare(p2.name))  // 按中文拼音升序
} else if (this.sorttype === 'desc') {
  arr.sort((p1, p2) => p2.name.localeCompare(p1.name))  // 按中文拼音降序
}
```

> `localeCompare` 适合比较字符串，尤其处理中文拼音、字母大小写，比直接 `-` 减法更合适。

---

## 总结一句话

> **原始数据永不动，过滤排序全靠计算属性推新数组，Vue 自动把结果渲染到页面。**
